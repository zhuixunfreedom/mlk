# 战斗文档字段消费

execute 回包同时包含战斗模板、逐波出怪、出战单位、背景、资源和结算地址。本章保留字段表，使用类型名表达消费位置，不携带反编译源码。表中“缺省行为”是已有静态分析的归纳，不代表全部设备运行结果。

## 解析不等于消费

Document 保留底层 JSON，ParseCore 额外构造强类型子文档；没有 switch 分支，不等于后续访问器或通用 ResponseFilter 不会读到。需要分别确认解析、实际行为读取和服务端下发三个阶段。

部分早期摘要与后续修订不一致。本文采用已定位的修订：powerup_conf 被普通和自动战斗的 SP 升级按钮实际消费；bonus_sp_rate 参与开场 SP，不只用于展示。unit_help_rate 已确认展示读取，尚不足以证明其参与所有援军战斗数值；援军出场由 help_table 与玩家开关驱动。

## 结构约束

- units 是数组，客户端按下标组织文档；出战 UUID 还要有正确唯一性。
- monsters 是以数值模板 ID 字符串为键的对象；每条出怪 ID 必须能找到模板。
- appear_table 为波次→毫秒→出怪项两层数字键对象，不能使用任意文字键。
- wave_conf 必须覆盖实际波次，尤其是初始波；缺少配置的直接属性访问存在空引用风险。
- timezone_table 的键对应波次，值参与背景资源名与加载过滤；空表不是通用安全默认。
- help_table 可空，但若提供条目，应给完整可用的援军单位文档。

## 字段表

读取位置保留类型名，不使用源码行号定位；少数默认值只证明结构赋值，实际生效点仍需按下游消费核对。

## 表格之外的模板与行为字段

PieceParameter 还消费 no_heal、hit_frame、attackable_count、两段跑动帧、act_target_id、act_type_id、multi_hit_count、multi_hit_interval、attack_se、attack_se_at_once、attack_stage_effect、knockback_local_x、quick、speed、escape_speed、flag_check_offset_x、effect_x/effect_y、base_scale、at、knockback_damage_rate、animation、formation_change_boarder、wave_lose_pt、damage_xys 和 damage_multiplier。

quick、base_scale 与 damage_multiplier 在既有路径通常回退 1；escape_speed 可回退 speed。动画子键包括 attack、escape、stop、run、damage。缺项能回退不等于该默认行为与原作一致。

模板还有 offset_y_base/front_offset_x_base，用于生成位置和触发范围。reach 由 TriggerRange 路径消费，不能因 Piece.Init 未读取就列为整个战斗无用字段。taghness 在已有检索范围主要属于列表和详情展示；未找到战斗读取不是穷尽证明。

## 三个容易混淆的出怪量

scale 主要影响视觉尺寸、偏移与体型表现；powerup_rate 在模板／params 的 HP 与 AT 上继续乘算；gauge 控制血条。三者独立，均不能因为服务端不亲自计算而称作死配置。

params 是克隆模板后合并的单怪覆盖。具体 catalog 紧凑格式怎样转为 params，属于服务端装配，不应把未装配的顶层 hp/at 随意当作客户端已经读取。

powerup_rate 与阶段额外 monsterPowerupRate 组合时，已有消费路径对攻击侧额外倍率有上限处理，HP 侧可能不共享同一封顶。不要把一个通用乘数应用到所有分支。

## 武器、SP 与援军

weapon_rate_hash 按 difficulty_id 字符串选择，再按 slash_rate/rush_rate/hit_rate/arrow_rate/magic_rate/gun_rate/heal_rate 读取，缺失一般回落 1。数字难度序号不能代替 normal/hard/very_hard 字符串键。

bonus_sp_rate 作用于编队 bonus_sp 汇总。seed_attribute_rates 可改变种子伤害、成本、冷却和效果值。seed_atack_rate 的既有拼写必须保持；零值可用于禁用种子技，省略键则常回退 1，二者不等价。

help_table 的时间键控制 NPC 援军，受教程状态和玩家援助开关影响。unit_help_rate 的 UI 文案已证，战斗数值语义需独立追踪。

## 背景选择与结果

background map 的各层被遍历，再按 timezones 筛选；background_id 不直接选 map 行，而与时区 ID 拼 bundle 资源名。参数表、资产清单和实际 bundle 必须相互闭合。

ap_use_url、result_url、lose_url、next_page_message 决定扣点、结算和离开战斗的链路；其合法性是服务端契约。逐怪 rewards 再用于战斗掉落表现和结果汇总，服务端发奖还必须以持久化会话与奖励快照为准。

## 需要保持的防护

缺少魔物模板、波次配置或 powerup_conf 当前档位可能在客户端触发无保护下标。talent_skill 部分字段使用字符串数值解析；若启用该分支，不能下发空数字串。结构齐备的验证应在服务启动或发布期完成，避免返回半份战斗文档。

部分 wave_conf 字段仅确认强类型构造，没有穷尽追踪所有生效点；反射、拼接键和资源内逻辑也不一定能被字面量检索覆盖。这些结论来自静态分析，未经客户端运行验证。
