# 页面结构与交互全集

本表整理 CN3.5 页面分析，保留 242 个配置页及 BOOT、Opening 两个系统节点，共 244 行。页面键已与 app_conf 全集核对。技术表的数据关系保留，读取位置使用类型名而非源码定位信息。

## 怎样理解本表

“所需接口”描述 requireData 的缓存键与 path；“出边交互”记录从本页出发的跳转；“UI 组件”统计动态部件、共享部件、partial 与 widget。JSON 中把组件放在同一对象里，不代表它们在同一 Transform 树中，挂载规则见[UI 生命周期](02-UI挂载与页面生命周期.md)。

接口与状态列基于历史分析快照，数据时点为 2026-09-27 及其后的追加记录，并非当前服务的逐页验收结果。当前能进入或能操作，必须核对实际路由、回包、缓存与资源。

| 标记 | 含义 | 不能据此推出 |
|---|---|---|
| real | 当时登记为业务实现 | 所有分支或资源均完成 |
| empty | 有空态读面 | 对应玩法已实现 |
| unsupported | 明确拒绝，通常为业务 modal | 玩家写操作成功 |
| preset | 正常启动缓存已提供该键 | 缓存失效后路径必然存在 |
| gap | 当时未找到对应路由 | 当前版本仍未注册 |
| ok | 当时 requireData 均有着落 | 全页实机渲染通过 |
| blocked | 当时有 gap | 页面永远不可进入 |
| nord | 无 requireData | 没有任何隐藏的数据依赖 |

历史统计为 429 条 requireData、175 个唯一 path，配置 OnClick 边 190 条、已归属代码边 59 条，另有变量目标和未归属调用。分类属于整理规则，不是原服官方功能划分。BOOT/Opening 计入系统节点后，状态统计与 242 个配置页数量需分别理解。

## 路径和导航的限制

尾斜杠、`.json` 后缀和 query 不是可任意互换的写法。已有服务端注册补足了一些尾斜杠形式，但不能据此认为 `/users/preset_data` 与 `/users/preset_data.json` 自动等价。缓存命中时可以暂时不发请求；expires、force_update 或冷启动会重新暴露路径依赖。

配置和静态调用确认的是“存在跳转意图”。目标页键缺失、prefab 不存在、变量 PageMessage、服务端下发 next_page_message，都可能改变真实导航结果。历史继承关系只作为待复核参考，不引入退役版本代码或资源。
