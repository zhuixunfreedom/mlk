# 协议与架构摘要

本页是自行整理的实现说明，不复制客户端源码。

CN3.5 桌面服务与 gomobile 共用 cn35app.Run。服务先加载卡牌模板与资源名元数据，再装配账号、会话和各领域存储，最后注册协议与业务路由。桌面命令收集配置；移动端引导器解压后端配置，调用 mobile.Start，在回环地址启动相同服务。

请求经 httpapi、协议解码与领域操作进入 cn35store。SQLite 保存账号、货币、库存、进度和领取/结算幂等记录；静态 JSON 提供页面配置、关卡与模板参考。跨领域状态变更和幂等台账在同一事务提交，静态文件不替代玩家存档。

app_conf 的服务端源文件可以保留注解；RenderWire 剥离注解并保持所需对象键序后输出紧凑 JSON。UI 恢复通过页面配置、requireData、服务端返回字段与消息驱动，不修改客户端 DLL。页面挂载成功不等于返回、销毁、输入遮挡等交互均已验收。

同伴读取优先采用已发布 DB 模板，其余回退 cards；魔宠继续使用 cards。战斗行为由内嵌数据富化；重建默认值、社区数值与官方样本的来源分别见文件注释。资源名清单与自备 Unity bundle 必须配套，字段存在不表示素材齐全。

接口文档可由 `make api` 从实际路由生成。/account 使用二进制帧，游戏业务存在 AES+zlib 等协议封装，浏览器 Swagger 不会自动替游戏客户端加解密。未实现接口和数据缺口仍须如实标注。
