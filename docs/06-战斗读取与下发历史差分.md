# 战斗读取与下发差分：2026-10-02 分析快照

本章保存 2026-10-02 分析的技术发现，用来理解“有配置、能开战、数值正确”之间的区别。下表不是当前代码的缺陷清单；其后未重新执行全量服务响应差分，因此不能靠本表判定某个缺口是否仍然存在。

## 差分需要比较三个集合

catalog 已配置哪些字段、execute 真正下发哪些字段、客户端具体行为读取哪些字段，是三种不同证据。列表页面发过一个字段，不保证 execute 的 quest 子文档也发；强类型解析存在，不保证已找到最终生效点。

2026-10-02 快照中的最小战斗集合包括单位面板、魔物、出怪、资源和结算。已配置的武器倍率未进入当时 execute 回包；开场 SP、种子属性和多项波次行为也存在缺项或默认回退。背景、powerup_conf 则确有活消费，当时统一取全局默认，并非“客户端不用”。

## 模板和数据覆盖

历史默认魔物行为层覆盖所统计的 29 个键中的 16 个。其余 no_heal、quick、escape_speed、flag_check_offset_x、第二段跑动帧、animation、formation_change_boarder、wave_lose_pt、damage_xys、damage_multiplier、attack_se_at_once、knockback_damage_rate 部分由补缺层提供，部分回退通用值。默认存在只能降低缺项风险，不能证明行为精准。

该时点快照记录：战斗使用 111 种魔物，其中 52 种社区基础 HP/AT 不全；整个 1052 条魔宠目录有 526 条缺 hits。部分缺项由纪念版或逐怪 params 补足。asset_names_extra、逐关 bgm_name 与 next_page_message 当时没有独立配置，全走公共回退。这些数量不能自动作为后续版本统计。

## powerup 的基值口径

历史抽验发现，逐怪 hp/at 是本地数值草案的过程值，不能从模板基础值简单推导；同条另带 powerup_rate=2.5。客户端还会在装配面板上乘该倍率。

因此先定义 hp/at 是“倍率前基值”还是“已含强化的终值”。若已经含强化，应避免再发非恒等倍率造成重复放大；若是基值，则透传乘数有其用途。scale 视觉缩放、gauge 血条和 powerup 数值强化不得合并处理。

## 零值与缺失的语义

seed_atack_rate=0 可以禁用种子技；缺键常按 1.0。若列表装配仅在值非零时下发，会把禁用变成启用。两份早期分析对 execute 是否也有相同条件分支记载不一致，本文不直接判定两处都错；应分别检查列表和 execute 当前装配路径。

适合的模型是区分未配置与显式零，或在已确定字段语义时明确输出零值，不能只用省略规则减少键数。

## 结构闭包与模式切换

每条出怪 ID 必须有 monsters 模板；wave_conf 与 appear_table 波次应一致，初始波存在；timezone_table 与背景资源及 asset_names 对齐。旧快照 160 关的波次键曾全部匹配，这只是该数据版本的校验结果。

pattern_conf 一旦启用会改走模式出怪，不应把它当作普通时间表的附加注释。接入持续伤害、限时、援军、陨石或前后剧情时，既要准备字段，也要理解相应分支和完整资源闭包。

## 使用这份差分推进实现

1. 对当前 catalog、装配代码和实际解密回包重新做字段比较，确认旧缺口是否仍存在。
2. 优先核对直接乘数与显式零，避免静默默认导致数值走样。
3. 核对 wave、模板、SP 升级档位和背景的结构完整性；数据不全时拒绝发布或开战。
4. 对未获原始来源的数值，使用明确重建策略，不伪造官方全表。
5. 固定战斗条件验证面板、乘数、SP、波次和奖励；历史静态分析不能替代实机。

unit_help_rate 的展示消费已证，但援军数值语义在旧材料中存在推断，不把它升级成确定事实。wave_conf 部分成员仅证明构造解析；未找到下游使用时保留待验证状态。
