# 资源接入与验证流程

本文描述使用者自行准备的 Unity 资源怎样通过服务端清单与远端目录下发。仓库不包含原 APK、模型、图像、签名或实际账号材料。资源格式校验、可下载、客户端可渲染和账号持有是不同验证步骤。

## 两类资源通道

整包基线资源随客户端版本准备，小更新通过服务端远端叠加层提供。基线目录与远端目录职责不同：不要把更新文件直接放进客户端基线树来代替服务器下载流程，也不要手改生成清单伪装远端条目。

配置与资源索引可明文或压缩下发，bundle 使用普通二进制下载。客户端按资源类别改写 urlName，同伴可能请求 unit_v2 路径；物理目录名与请求逻辑名需要通过服务端映射核对。

## 输入检查

| 检查项 | 约束 | 失败时处理 |
|---|---|---|
| 文件名 | 匹配 `.Android.unity3d` 规则 | 拒绝；隐藏文件和其他平台文件不纳入 |
| 文件头 | UnityWeb 或 UnityRaw 魔数 | 拒绝错误格式 |
| 逻辑分类 | 能映射到已支持 AssetType | 不猜测未知类型 |
| 稳定性 | size/mtime 连续扫描一致，或足够旧 | 新拷贝阶段进入 pending |
| 模板／资源闭包 | catalog、索引和需要的资源族一致 | 缺项明确诊断 |

扫描默认间隔和稳定阈值以随包实现为准。已有规则通常使用约 10 秒的新文件等待，避免客户端下载尚未写完的内容。

## 服务端装配与版本

运行时指定 `-remote-assets <远端目录>`。远端集合增删推动清单版本，version_info 的 asset_info_version 与清单首行应一致。md5 行让客户端走远端下载；已有短清单使用 MD5 的前 8 位小写十六进制作为协议字段，完整 SHA-256 用于本地字节一致性验证，两者不能混淆。

不要删除远端版本状态文件让版本回落。客户端已经缓存较高版本时，较低版本可能无法让它刷新。旧 bundles 兜底目录不能代替已明确的远端叠加通道。

## 发放前验证

1. 检查远端诊断的有效、rejected、pending 项和版本。
2. 获取实际下发清单，核对逻辑名、类别、版本、下载标记与摘要。
3. 按客户端改写后的 URL 下载，核对字节数和完整 SHA-256。
4. 校验模板引用、清单与所有所需资产族闭包。
5. 在隔离库确认目标账号存在，验证发放候选的内容摘要与来源键。

上述可以不连接设备进行，但不能因此宣称已渲染成功。

## 发放与持久化

发放配置携带来源版本、模板 ID、初始状态和台账键。先计算 content_sha256 防止配置漂移，再执行只读 preview；确认目标迁移齐备后，才在隔离副本演练 apply。

preview 不迁移、不初始化库、不写玩家资产。apply 校验 ID 在 catalog 中、初始等级合法、列表无重复且来源键有效；持有写入与发放台账同事务。重放应零新增或返回已应用。

正式有数据 state 操作前需要一致性备份并核对匹配二进制。发放的追加记录不提供删除型回滚；撤下远端资源只停止后续下发，已有库存仍保留，缺图时可能降级。

本文的操作说明只涉及运行时工具。具体 CLI 以随仓库的 mercdb 子命令与配置 schema 为准，不应据文档假定某个命令可调用。

## 客户端验证

不改客户端业务 DLL。已有地址连接正确、清单版本更新后，检查下载缓存、列表、详情、立绘、模型和战斗。跨 Unity 小版本生成的 bundle，即使静态序列化格式相同，也必须在实际运行时验证；下载成功不能证明 AssetBundle 被接受。

同伴资源不仅有主模型，还可能需要 list、large、btn、square、rectangle、gray_btn、silhouette 等图标／立绘族。逐项检查，不用某一处显示正常代表全族齐备。日志和截图只保留本地核验所需，公开说明使用脱敏结论，不上传实际账号和设备资料。

## 记录与常见故障

记录资源来源类别、文件摘要、清单前后版本、下载校验、发放与重放结果、实际客户端测试范围和缺项。文档不登记个人目录、账号值、设备地址或原始证据链接。

| 现象 | 首先检查 |
|---|---|
| 下载 404 | 逻辑名改写、URL 版本和索引 |
| 仍使用旧资源 | 版本是否递增、客户端是否拿到新清单 |
| rejected | 扩展名、魔数、AssetType |
| pending | 文件是否仍写入或太新 |
| 发放拒绝 | 模板、迁移、摘要、来源键与归属 |
| 列表有卡但缺图 | 图标与立绘族是否完整 |
| 下载成功却不渲染 | bundle 格式与实际 Unity 运行时兼容 |

以上为流程说明。资源发放、客户端构建、签名或设备安装需在本地按自身环境执行。
