# 日常入口与页面跳转

首页入口通过 function_portal 决定红点和功能项，再以 function_portal_list 驱动日常页面的右侧列表。行内 show_page_message 提供二级跳转，恢复可以在服务端配置完成。

```text
首页日常入口
  → Stack 打开 MainCharaDailyPage
    → ListParts 读取 function_portal_list
      → 行点击解释 show_page_message
        → 二级页面及其 requireData
```

## 行文档与路径

`/users/function_portal` 提供 function_portal 与 function_portal_list，实际读面兼容 GET/POST 并按 force_update 更新。列表行有 id、texture_asset_name、show_page_message。

PageMessage 的 name 对应 app_conf 页键，base 对应可加载 prefab，method=Stack 表示入栈。把 name 写成脚本类名，或给不存在的 base，可能得到空配置、空白页或实例化失败。无专用 prefab 的页可按已确定的配置使用 `Common/Pages/Basic`，不在客户端业务代码加补丁。

## 已整理的五类入口

| banner 逻辑名 | 页面键 | prefab | 二级依赖或行为 |
|---|---|---|---|
| common/bnr_college | CollegeSelectInterface | Common/Pages/Basic | `/college/`，再到学习／执教分支 |
| common/bnr_unit_friendship | UnitFriendshipMainPage | Common/Pages/Basic | 羁绊列表、魔宠与相关编队 |
| common/bnr_red_diamond_shop | RedDiamondShop | Common/Pages/RedDiamondShopPage | 商店列表、buy、refresh |
| common/bnr_true_love | TrueLoveMainPage | Common/Pages/Basic | truelove_main_info，进入小镇或列表 |
| common/bnr_unit_exchange_150201 | UnitExchange | Common/Pages/Basic | 交换列表，再进单位详情 |

素材名是协议标识，仓库不附原 banner 图片。缺素材要登记，不能只因为 conf 存在就展示一个无法加载的按钮。

## 二级与再下一级

CollegeSelectInterface 的 study/teach 分别到 CollegeStudyView、CollegeTeachView。UnitFriendshipMainPage 可进入 FriendlyList、NextInfo 与 AreaSelect。TrueLoveMainPage 进入 TrueLoveTownPage 或 TrueLoveList；UnitExchange 进入 UnitExchangeUnitDetail。商店购买和刷新是页内业务请求。

function_portal 还可提供 chara_buff_button_key、fate_button_key 及禁用状态，供其他主页功能使用。这些是入口选择，不代替相应域的完整玩法。

## 入口恢复的验收边界

2026-10-03 的分析记录五个二级页可达，但学园、羁绊、真爱与交换等多个依赖仍为空态；每日商店另有实现。该范围保持原样，入口可达不等于四个玩法完成。

要检查 PageMessage 正确、prefab 存在、requireData 的实际回包、资源加载、入栈返回和页面残留。红点关闭也不证明业务内容已领取。配置缓存需要版本更新和重新获取，不能仅重复返回旧页面判断修复已作用。
